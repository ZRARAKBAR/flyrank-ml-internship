FlyRank AI Internship Retrospective

When I started the FlyRank internship, my main goal was to understand how machine learning could be applied to a real problem rather than only learning algorithms through classroom examples. In Week 1, I was still getting comfortable with the internship workflow itself: GitHub, Google Colab, Hugging Face, notebooks, datasets, and the process of turning a broad idea into an actual machine-learning problem. I selected the Content Refresh Prioritization lane because I wanted to investigate whether historical search-performance information could help identify webpages that should receive attention first.

My original research question was: “How can machine learning identify webpages that should be refreshed first based on their search performance trends?” As the internship progressed, I learned that the difficult part was not simply training a model. The more important work was defining what the model should predict, avoiding leakage, choosing an appropriate validation strategy, and being honest about what the results actually mean. I therefore framed the project as a supervised classification problem using page-level observations and a trend-based target. I also learned why fields directly derived from the target should not be used as predictive features because doing so could make the evaluation look stronger than it really is.

One of the biggest changes in my approach was moving from thinking about “getting a high accuracy” to thinking about whether a model provides useful decision support. The final system is intended to help an editor prioritize webpages for manual review. It does not claim to predict Google's ranking algorithm or guarantee that refreshing a page will improve its performance. The model produces a prioritization signal, after which a human should review freshness, search intent, completeness, relevance, and competitiveness before deciding whether to refresh the page. This changed how I think about machine learning: a technically correct model is not automatically a useful product unless its output fits a real decision process.

The project also changed how I approach validation. Instead of treating a single accuracy number as proof that the model works, I learned to compare the model against a transparent baseline on the same evaluation data and consider the majority-class/base-rate context. I also learned the importance of checking false positives, false negatives, uncertain predictions, and disagreements between the baseline and the model. The final project therefore became as much an exercise in responsible evaluation as in model training.

If I continued the project, I would build a stronger production-oriented version with more recent and diverse data, additional editorial features, stronger temporal validation, and monitoring for performance changes when the model encounters new clients or future search behavior. I would also explore whether a ranking formulation would be more appropriate than classification for directly ordering refresh opportunities. Most importantly, I would validate the recommendations with real editorial outcomes rather than assuming that a model prediction automatically represents business impact.

The three most transferable lessons I learned are, first, problem framing matters as much as model selection. A well-defined decision and target make the rest of the ML pipeline much clearer. Second, validation and leakage control are essential. A model can produce impressive numbers while still being misleading if the evaluation design is weak. Third, AI is most useful when I remain responsible for the final judgment. During the internship I used AI tools such as Claude and ChatGPT to explain concepts, explore approaches, troubleshoot problems, structure documentation, and review my work. I still had to understand the resulting code and decisions, check the outputs, and determine whether they were appropriate for my project.

The biggest difference between Week 1 and the end of the internship is that I no longer see machine learning as simply “train a model and report accuracy.” I now see it as a complete process: define the decision, understand the data, prevent leakage, establish a baseline, validate honestly, interpret errors, communicate limitations, and connect the result to a real human workflow.
